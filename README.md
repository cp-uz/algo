# CP.UZ Algoritmlar

CP.UZ Algoritmlar is the Uzbek adaptation of [cp-algorithms](https://cp-algorithms.com/). The repository contains 163 tracked article routes, a deterministic static renderer, a review state machine, upstream-change detection, and a moderated browser editor.

The project is pinned to the cp-algorithms commit recorded in [`UPSTREAM_PIN`](UPSTREAM_PIN). Article adaptations remain subject to CC BY-SA 4.0; repository tooling is licensed separately under [`LICENSE-CODE`](LICENSE-CODE).

## Canonical sources

There are only two canonical mutable inputs:

- `docs/<category>/<article>.md` — human-editable Uzbek Markdown. Front matter contains only the stable `article_id`.
- `data/articles.yml` — article identity, source/version data, translation state, review records, publication state, and append-only review history.

Everything below is generated by `make build` and must not be edited manually:

- `data/articles.json`
- `data/review_queue.csv`
- `site/`
- `MANIFEST.sha256`

The builder hashes `docs/` before and after rendering and fails if a build changes canonical article content.

## Quick start

```bash
make setup
make check
make dev
```

Local URLs:

- Public site: `http://127.0.0.1:8000/`
- Binary Exponentiation: `http://127.0.0.1:8000/algebra/binary-exp/`
- Moderation dashboard: `http://127.0.0.1:8000/moderation/`

`make dev` enables development-only local login. Production never exposes that login route.

## Terminal review workflow

Edit only the Markdown article:

```bash
code docs/algebra/binary-exp.md
```

Record a technical decision in one command:

```bash
python scripts/review.py approve algebra/binary-exp.md \
  --type technical \
  --reviewer "Reviewer Name" \
  --notes "Proof, implementation and complexity checked."
```

Then build and verify:

```bash
make build
make validate
```

Language approval is rejected until a current technical approval exists for the same article body and source commit. Review decisions retain reviewer, timestamp, content hash, source commit, notes, and audit history.

## Web editing workflow

Authenticated contributors open an article, select **Tahrirlashni taklif qilish**, edit Markdown with a sanitized live preview, and submit a proposal. Submission does not change `docs/`.

A moderator sees old and proposed text, a line-by-line diff, author, time, and summary. They may approve, reject, or request changes. Local development applies approved changes atomically to the repository. Production uses a server-side GitHub token to create a branch and pull request (recommended) or a direct commit. Tokens are never sent to browser JavaScript.

## Useful commands

```bash
make help
make build                 # generated metadata, HTML and checksums
make validate              # strict verification; does not repair files
make test                  # pytest suite
make check                 # build + tests + validation (CI sequence)
make serve                 # read-only static server
make dev                   # site + editor + moderation backend
make review-status
make review ARTICLE=algebra/binary-exp.md TYPE=technical REVIEWER="Name"
make upstream-check TO_COMMIT=<40-character-sha>
make backup-proposals
make qa-algebra             # fast deterministic C++ smoke checks
make qa-algebra-full        # slower exhaustive/randomized checks
```
